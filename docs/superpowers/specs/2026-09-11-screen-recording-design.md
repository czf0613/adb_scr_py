# 屏幕录制设计

用户已批准实施，音频按后续决定统一 AAC，不引入 Opus 或音频转码。

## 行为

- `await AndroidDevice.start_recording(output_file: str) -> None` 开始录制；`await AndroidDevice.stop_recording() -> None` 等待文件完成。每台设备同时最多一个录制，重复 start 报错，重复 stop 安全。
- 已有解码帧时立即使用原生 NV12 快照生成首个 H.264 关键帧。没有已解码画面时明确报错，不等待手机送来 I 帧。
- 录制期间订阅解码帧，使用实时、禁止帧重排的 VideoToolbox 硬件 H.264 编码器。根据真机反馈，码率、画质、Profile 和关键帧间隔采用系统默认值，不设置速度优先提示。原始 BGRA8/JPEG 功能保留。
- 静止画面不依赖新的视频包：开始保留首帧，结束提交缓存尾帧并设置结束时间，即使中途无包也能产生具有正确时长的 MP4。
- 输出画布使用首帧尺寸；旋转后在原生层等比适配、居中留黑，不拆分文件。
- scrcpy AAC 配置及压缩包直接交给原生 AVAssetWriter 封装，不在 Python 或系统库中重新编码音频。
- 启动 scrcpy 前读取 `ro.build.version.sdk`：API >= 33 使用 playback + audio_dup，30–32 使用 output，低于 30 关闭音频。查询失败/非法结果使连接失败，避免猜测音源。
- 音频捕获被服务端明确禁用时保留视频/控制会话，并记录音频不可用；已知音频不可用时录制为视频文件并明确记录日志。录制中音频异常记录错误，停止时报告，正常停止仍尽力完成已有文件。
- 不覆盖已有输出文件，不自动创建父目录。失败或取消的开始不得遗留活动录制；结束/断连必须等待编码及写入排空，文件错误通过异常或断连日志报告。

## 时间与并发

设备音视频 PTS 共用微秒时间基准。连接期间持续消费 AAC，维护 `(设备 PTS, 本机 monotonic)` 锚点；开始按锚点外推设备时间，不把久未变化的视频 PTS 当作当前时间。音视频统一减去录制原点；音频边界按 AAC 包处理，最大偏差为一个包（48 kHz / 1024 samples 约 21.3 ms）。本机与设备时钟映射包含传输延迟，不能宣称硬实时精度。

原生录制器独立于 H.264 解码器，通过解码器串行队列持有引用。配置变化时解绑旧解码器、创建新解码器、重新绑定；录制保持存活。录制队列只接收 retain 的帧和复制的音频包，队列有界，过载时视频允许丢弃中间帧，音频不能静默丢失。编码和文件写入不能阻塞解码器帧队列。

所有可能等待的原生 Python 调用使用 `asyncio.to_thread()` + `complete_on_cancel()`。原生入口在等待 mutex/GCD/编码期间分离 Python 线程状态，支持普通 3.10/3.14 和 free-threaded 3.14t。停止先解绑视频订阅，阻止新音频入队，然后排空并完成文件，再释放资源。

## 验证

合成 H.264/AAC 验证首帧关键帧、静止录制时长、动态帧、音视频 PTS、AAC 压缩包保留、旋转、快速开始停止、重复录制、并发关闭和无帧/文件错误。模拟 ADB 与 socket 验证 API 分支、连接顺序、音频禁用/EOF/半包、取消与断连清理。普通 3.14 原地构建，3.10/3.14t 在独立临时树构建和测试，检查 wheel/sdist 内容。仅相关无设备测试，真机阶段等待用户连接手机。
